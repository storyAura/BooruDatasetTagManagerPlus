# BooruDatasetTagManager+ v1.2.8（中文）

**新功能**

- **Tag 推标接入 PixAI Tagger v1.0 与 WD EVA02 2026 Canary**。官方仓库是 PyTorch / safetensors，应用仍只跑 ONNX Runtime，所以下载对应的社区 ONNX 导出。界面名称用官方型号。写标仍只保留 **general** 与 **character**。
- **PixAI Tagger v1.0**（`pixai:v1.0`）：从 [noaione/pixai-tagger-v1.0-onnx](https://huggingface.co/noaione/pixai-tagger-v1.0-onnx) 下载 `model.onnx`、`model.onnx.data`（约 2 GB）和 `tags.json`。词表 30,877。输入边长 1008，等比缩放并加黑边（小图也会放大），RGB、NCHW，logits 做 sigmoid。默认阈值 general **0.17**、character **0.27**（模型卡的 macro-F1 工作点）。v0.9 的拉伸预处理和 0.30 / 0.85 不变；两个版本的阈值按模型分开保存，旧配置里的 PixAI 阈值记到 v0.9。GUI、CLI `onnx-tag --model pixai:v1.0` 和 YOLO「在 Tag 推标中打开」共用同一套服务。CPU 推理会明显变慢。
- **WD EVA02 2026 Canary**（`[WD14] eva02-large 2026 canary`）：从 [Misaka41Z/wd-eva02-tagger-2026-canary-onnx-v2](https://huggingface.co/Misaka41Z/wd-eva02-tagger-2026-canary-onnx-v2) 下载 `model.onnx` 与 `selected_tags.csv`。架构与 eva02-large v3 相同，词表延到 2026-05（16,473 类）。默认阈值 general 与 character 都是 **0.61**（发布的 P=R 工作点 0.6094）。预处理仍是白边、不放大、BGR。若导出的输入是 NCHW，或分数落在 0–1 之外（原始 logits），会话会按形状换布局并补一次 sigmoid。默认模型仍是 eva02-large v3。
- **推理设备**：Tag 推标窗口可选择 **GPU**（DirectML，默认）或 **CPU**。选 CPU 时不再尝试显卡；选 GPU 时若 DirectML 失败，仍退回 CPU，下次再选 GPU 会重新加载显卡会话。CLI：`onnx-tag --device cpu|gpu`。
- **批大小**：Tag 推标和 `onnx-tag --batch-size` 可一次送进多张图，默认 **1**，最大 8。模型输入若把 batch 固定为 1，会自动退回逐张推理。
- **专业模式**（默认关）：打开后按模型露出它真正有的额外参数。PixAI v1.0 可调版权 0.24、风格 0.15、元数据 0.17、分级 0.41，以及「写入风格」（默认关）、「写入元数据」（默认开）、「角色标签在前」。WD14 只有分级（类别 9；`sensitive` 这类裸名字会写成 `rating:sensitive`）。CL 有版权、元数据和分级，用该模型自己的默认阈值。PixAI v0.9 和 OppaiOracle 没有这些头。关闭时仍只写 general 和 character。CLI、YOLO 裁图推标和 LLM 自动 WD14 读取同一份已保存设置。
- **在当前图片标签中查找**（感谢 [@furjifurji](https://github.com/furjifurji)，[#1](https://github.com/storyAura/BooruDatasetTagManagerPlus/pull/1)）：图片标签侧边栏新增查找按钮，打开一个不阻塞主窗口的查找浮窗。浮窗支持查找下一个（Enter）/ 上一个（Shift+Enter）、区分大小写、全词匹配，Esc 隐藏。打开时会自动带入当前选中的标签。中文输入会通过词典找到对应的英文标签。浮窗与顶栏搜索框共用同一个搜索词。热键默认不绑定，可在设置里自行指定。顶栏搜索框现在也按行顺序逐个跳到匹配项，不再总是先停在前缀匹配上，所以「下一个」能走遍所有匹配。
- **复制标签时附带翻译**（设置 → 翻译 → 数据，默认关）：打开后，复制到剪贴板的文本为 `tag (翻译)`。在本程序内粘贴仍然只粘贴原标签。

**修复**

- 编辑标签单元格时，Ctrl+C / V / X / A / Z 现在作用于正在编辑的文本，不再被表格截走。
- 数据集浏览器：先用鼠标点选图片再用方向键移动时，起点改为刚点选的图片，不会再跳到别处。
- 查找浮窗第一次「查找下一个」可能跳过第一个匹配项。
- **角色标签审查：少标法与全标法结果几乎一样，并反复出现编造标签和泛类标签**。v1.2.7 让每个无颜色衣物都必须补颜色，而「颜色 + 真实标签」一律放行，于是出现 `white long sleeves`、`white school uniform`、`white eyepatch` 这类 danbooru 里不存在的标签；这些衣物被留在提示词里，少标法也就删不下来。现在带颜色的标签本身必须是 danbooru 词表里的真实标签，只对 danbooru 有颜色版本的衣物（`shirt`、`sailor collar`、`choker` 等）追问颜色；已经有 `blue one-piece swimsuit` 时不再追问 `one-piece swimsuit` 的颜色（之前会再得到一个 `black one-piece swimsuit`）；`leotard` 与 `one-piece swimsuit` 会被当作可能是同一件衣服交给模型二选一。`breasts`、`thighs` 等身体部位词和 `official alternate costume` 不再进入角色提示词（仍保留在数据集文件里），少标法也不放胸部大小；被模型归到「头发」的 `pom pom hair ornament` 在少标法下也会删除。用同一数据集实测（gemini-3.1-flash-lite），少标法提示词从 15–22 个标签降到 13 个，全标法 16–18 个，6 次运行都没有再出现编造标签。CLI `audit --style` 的帮助文字从 `sparse|dense` 改为实际可用的 `sparse|full`。
- **角色标签审查的 API 调用更稳**：审查向导新增「温度」设置（0–2，默认 **0.5**；之前不发送温度，用的是服务商默认值，常为 1.0，同一件衣服会在两次运行间变色）。模型若拒绝温度参数（o 系列等推理模型），立即改用服务商默认温度重发（不占重试次数），本轮其余请求也不再发送，并在用时一栏、debug.log 和 CLI 输出中提示。网络或中转站的临时错误（如 `HTTP 400 get_channel_failed`、429、5xx）会自动重试，最多 3 次（间隔 2 秒、4 秒），之前一次失败就结束整轮审查。单次审查请求 5 分钟未返回即中断并重试，不再沿用 LLM 设置里默认 3600 秒的超时。点「取消」仍立即停止，不会重试。

# BooruDatasetTagManager+ v1.2.8 (English)

**New**

- **Tag tagger adds PixAI Tagger v1.0 and WD EVA02 2026 Canary**. The official repos are PyTorch / safetensors; the app still runs ONNX Runtime only, so it downloads the matching community ONNX exports. Display names use the official model names. Written tags are still **general** and **character** only.
- **PixAI Tagger v1.0** (`pixai:v1.0`): downloads `model.onnx`, `model.onnx.data` (~2 GB), and `tags.json` from [noaione/pixai-tagger-v1.0-onnx](https://huggingface.co/noaione/pixai-tagger-v1.0-onnx). Vocabulary 30,877. Input side 1008, aspect-preserving scale with black padding (small images are upscaled), RGB NCHW, sigmoid on logits. Default thresholds general **0.17** and character **0.27** (the model card's macro-F1 operating points). v0.9 keeps its stretch preprocess and 0.30 / 0.85; thresholds are stored per model, and a saved PixAI pair from an older config is kept on v0.9. GUI, CLI `onnx-tag --model pixai:v1.0`, and YOLO detect's "open in Tag tagger" share the same service. CPU inference is noticeably slower.
- **WD EVA02 2026 Canary** (`[WD14] eva02-large 2026 canary`): downloads `model.onnx` and `selected_tags.csv` from [Misaka41Z/wd-eva02-tagger-2026-canary-onnx-v2](https://huggingface.co/Misaka41Z/wd-eva02-tagger-2026-canary-onnx-v2). Same architecture as eva02-large v3, vocabulary extended through 2026-05 (16,473 classes). Default general and character thresholds are both **0.61** (the published P=R point 0.6094). Preprocess stays white padding, no upscale, BGR. If the export's input is NCHW, or scores fall outside 0–1 (raw logits), the session switches layout and applies sigmoid. The default model remains eva02-large v3.
- **Inference device**: the Tag tagger window can use **GPU** (DirectML, the default) or **CPU**. CPU skips the GPU. If DirectML fails, that run falls back to CPU, and the next GPU selection loads a GPU session again. CLI: `onnx-tag --device cpu|gpu`.
- **Batch size**: Tag tagger and `onnx-tag --batch-size` can send several images at once. The default is **1** and the maximum is 8. A model whose input batch is fixed at 1 keeps running one image at a time.
- **Professional mode** (off by default): when on, the window shows only the extra heads the selected model has. PixAI v1.0 adds copyright 0.24, style 0.15, meta 0.17, and rating 0.41, plus "write style" (off by default), "write meta" (on by default), and "characters first". WD14 adds rating only (category 9; a bare name such as `sensitive` is written as `rating:sensitive`). CL adds copyright, meta, and rating at that model's own default threshold. PixAI v0.9 and OppaiOracle have none of those heads. Off, writes stay general and character only. CLI, YOLO crop tagging, and the LLM window's automatic WD14 pass read the same saved settings.
- **Find tag in the current image** (thanks [@furjifurji](https://github.com/furjifurji), [#1](https://github.com/storyAura/BooruDatasetTagManagerPlus/pull/1)): a new button on the image-tags sidebar opens a find window that does not block the main window. It supports find next (Enter) / previous (Shift+Enter), match case, and match whole tag; Esc hides it. It starts with the selected tag filled in. Chinese input finds the matching English tag through the dictionary. The window and the header search box share one search term. The hotkey is unbound by default and can be set in Settings. The header search box now also steps through matches in row order instead of always stopping at a prefix match first, so "next" reaches every match.
- **Copy tags with translation** (Settings → Translations → Data, off by default): when on, text copied to the clipboard reads `tag (translation)`. Pasting inside the app still pastes only the tags.

**Fixes**

- While editing a tag cell, Ctrl+C / V / X / A / Z now act on the text being edited instead of being taken by the grid.
- Dataset browser: arrow keys after a mouse click now move from the clicked image instead of jumping elsewhere.
- The find window's first "find next" could skip the first match.
- **Character tag audit: sparse and full gave nearly the same result, with invented and generic tags.** v1.2.7 made every color-less wearable take a color and accepted any "color + real tag", which produced tags danbooru does not have, such as `white long sleeves`, `white school uniform`, and `white eyepatch`. Those garments stayed in the prompt, so sparse could not prune them. A colored tag must now itself be a real tag in the danbooru vocabulary, and the audit asks for colors only on garments danbooru colors (`shirt`, `sailor collar`, `choker`, ...). It no longer asks for the color of `one-piece swimsuit` once `blue one-piece swimsuit` is confirmed (that used to add a second `black one-piece swimsuit`), and `leotard` / `one-piece swimsuit` are handed to the model as one possible garment to pick from. Body-part words such as `breasts` and `thighs`, and `official alternate costume`, no longer enter the character prompt (they stay in the dataset files); sparse also leaves breast size out, and sparse now also deletes `pom pom hair ornament` when the model files it under hair. On the same dataset (gemini-3.1-flash-lite), the sparse prompt went from 15–22 tags to 13 and full is 16–18, with no invented tag in 6 runs. The CLI `audit --style` help now reads `sparse|full`, which is what it accepts, instead of `sparse|dense`.
- **Character tag audit API calls are steadier**: the audit wizard gets a Temperature setting (0–2, default **0.5**; before, no temperature was sent, so the provider default applied, often 1.0, and one garment changed color between runs). If a model rejects the temperature (o-series and other reasoning models), the request is resent at once with the provider default (without using a retry), the rest of that run omits it, and a warning appears next to the duration, in debug.log, and in CLI output. Transient network or proxy errors (such as `HTTP 400 get_channel_failed`, 429, 5xx) are retried up to 3 times (2 s, then 4 s apart); before, one failure ended the whole audit. A single audit request that has not answered in 5 minutes is cut off and retried, instead of inheriting the LLM settings' 3600-second default. Cancel still stops at once and is never retried.
